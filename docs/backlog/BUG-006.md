# BUG-006: Category text is rendered as HTML in the expense list

**Reported by:** Tuan (QA)
**Severity:** High
**Environment:** Chrome 131, app at http://localhost:3000, seeded data

## Steps to reproduce

1. Open the app, add an expense with date `2026-03-21`, amount `1`, note `probe`, and category
   `<b>food</b>`.
2. Look at the new row in the list.
3. Repeat with category `<img src=x onerror="alert('xss')">`.

## Expected

The category cell shows the text exactly as typed (`<b>food</b>`), the same way the note
column shows `<b>` literally. No bold, no popup.

## Actual

Step 2 shows **food** in bold. Step 3 pops an alert as soon as the list renders, and again on
every reload. Anything typed into the category box runs in every browser that opens the page.

## Notes

Note text is already escaped (tried the same payload there, it shows literally). Category and
the summary list look like the two places that were missed. The API accepts the value as-is and
that seems fine for now; the problem is the rendering.
