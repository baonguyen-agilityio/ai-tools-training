# BUG-007: Monthly summary accepts months that do not exist

**Reported by:** Tuan (QA)
**Severity:** Low
**Environment:** curl 8.7, app at http://localhost:3000, seeded data

## Steps to reproduce

1. `curl -i "http://localhost:3000/api/summary?month=2026-13"`
2. `curl -i "http://localhost:3000/api/summary?month=2026-00"`
3. `curl -i "http://localhost:3000/api/summary?month=2026-1"`

## Expected

Steps 1 and 2 return `400` with an error body, the same way step 3 does. There is no month 13
and no month 0, so the request is invalid, not an empty month.

## Actual

Step 3 returns `400 {"error":"month must be YYYY-MM"}` as expected.
Steps 1 and 2 return `200` with `{"month":"2026-13","total":0,"byCategory":{}}`, which looks
like a real month that simply had no spending.

## Notes

Found while scripting the month-end export: a typo in the month silently produced a zero report
instead of an error. The UI month picker cannot send these values, so this only affects API
callers.
