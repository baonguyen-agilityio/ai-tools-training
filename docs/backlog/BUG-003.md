# BUG-003: Deleting an expense twice reports success both times

**Reported by:** Tuan (QA)
**Severity:** Medium
**Environment:** curl 8.7, app at http://localhost:3000, seeded data

## Steps to reproduce

1. `curl -i -X DELETE http://localhost:3000/api/expenses/a1`
2. Run the exact same command again.
3. Also try an id that never existed: `curl -i -X DELETE http://localhost:3000/api/expenses/does-not-exist`

## Expected

Step 1 returns `200`. Steps 2 and 3 return `404` with an error body, since there is nothing to delete.

## Actual

All three return `200 OK` with `{"id": "..."}` echoing whatever id I sent.
A client has no way to tell whether anything was actually removed.

## Notes

Found while writing an integration test for the delete flow. Nothing breaks visibly in the UI,
but this hides real errors (wrong id, double-click, stale page) and will bite us when another
service starts calling this API.
