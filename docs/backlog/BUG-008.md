# BUG-008: Expenses accept dates that do not exist

**Reported by:** Code review on PR #21
**Severity:** Low
**Environment:** Node 24, API called with fetch, temp `EXPENSES_FILE` seeded from `data/seed.json`

## Steps to reproduce

1. `curl -i -X POST http://localhost:3000/api/expenses -H 'content-type: application/json' -d '{"date":"2026-02-31","amount":5,"category":"food","note":"probe"}'`
2. Repeat with `"date":"2026-04-31"` and `"date":"2026-02-30"`.
3. Repeat with `"date":"2026-13-01"`.
4. `curl -i "http://localhost:3000/api/summary?month=2026-02"`

## Expected

Steps 1 and 2 return `400` with an error body, the same way step 3 does. February has no 30th
or 31st and April has no 31st, so the request is invalid and nothing should be saved.

## Actual

Step 3 returns `400 {"error":"date must be YYYY-MM-DD"}` as expected.
Steps 1 and 2 return `201` and save the expense with the impossible date exactly as typed
(`"date":"2026-02-31"`). Step 4 then counts the `2026-02-30` and `2026-02-31` expenses in
February's total (seeded 315.29 becomes 325.29), so a typo in the day silently changes a real
month's report.

## Notes

Same family as BUG-007: the format is checked but not whether the day exists. My guess is the date
check leans on `Date.parse`, which quietly turns `2026-02-31` into March 3 instead of failing.
The UI date picker cannot send these values, so this only affects API callers.
